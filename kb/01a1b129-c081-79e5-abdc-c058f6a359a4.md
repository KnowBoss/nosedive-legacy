# Test

Legacy nosedive's `test` (its command doc `1e62a79d`, test@2), on a hero migrated to core, without the backlog sweep and without writing anything.

## Selecting gates

A gate is any doc a link names with a rel ending in `.gate` whose `meta.test-script` is a hero-relative path; its kind does not matter.

- `test`: the `test.gate` links of the dive this worktree holds, found as work finds it: an open dive of work's dive kind whose `diver` carries this checkout's holder token. No dive held is refused, naming `jump` and the named form.
- `test --full`: also every `test.gate` on the dive's feat, on each repo doc it scopes, and on every feat reached from the dive's feat through links whose rel names `.feat` as its role, in either direction. Nothing else is followed, so another dive's gates are never swept.
- `test <gate>...`: the named gates, by quid or hero-relative path, in the order given. A gate is declared by the docs with a `.gate` link to it. One declaration is used; several are refused naming each, unless the held dive is among them, which then answers. `--via <doc>` narrows the declarers to that doc and the docs its links reach, before the held dive is considered; a gate with its own `scopes:` needs no declarer.

Selecting no gates is a failure.

## Running them

Each gate runs in its own process, one after another, its output streamed as it comes. Its script exports `run(ctx)`; a `false` return or a throw fails it. A failing gate does not stop the run; the summary names every failure, and the exit is 1 if any gate failed whose declaring link is not `test-is-flaky: true`. A flaky failure is a warning.

`ctx` is legacy's:

- `bridgeRoot`: the hero's absolute path.
- `gateId`, `introducedById`: the gate, and the doc whose link selected it.
- `diveId`, `featId`: the held dive and its feat, empty when none.
- `repos`: by repo `name`, `{ id, root }`, root hero-relative, for the gate's scopes: its own `scopes:` when it has the key (`[]` meaning none), else its declarer's.
- `resolve(quid)`: the parsed doc, `{ fm, body }`; it throws when no doc has that quid.

A scope's checkout is used as it is when present, saying when it is not at the scope's `ref`. A missing one is hydrated as hydrate-repo.workspace does, at the scope's `ref`, else trunk, naming the commit. The first gate to claim a repo decides its ref; a later one wanting another is named with both refs. An empty `repos` is named before its gate runs.

A gate whose doc or script has uncommitted changes is named on stderr, and runs.
