# Held dive

The dive the hero's branch names as a dive branch, `nosedive-<holder token>-<dive id>`: a doc of legacy's dive kind in the hero, as legacy nosedive wrote it, or of work's, which names its dive branches alike, its feat and its scope entries keyed by registered repos, each with its `ref`. A hero on any other branch holds none. A dive that is over, or whose `diver` carries another token, is refused, as the loop refuses it.

Either shape is read as it is. A legacy dive hangs from a doc by a state link, over once it says landed or bailed, even for the memo legacy nosedive left; its feat is `meta.feat`, else `meta.effort`, else the doc that links it. A work dive has no state link, hangs by `dives.feat`, names its feat in `meta.feat` and is over by `meta.outcome`: a dive with a state link takes its end from that link, any other from its outcome.

It takes work's dives too so `test` runs a dive's gates in a hero wearing both capes, whichever loop jumped it (see dive, Wearing work too). It repeats the loop's rule rather than calling legacy's dive-on-deck, which refuses where test only finds nothing; it changes when the dive branches do.
