# Legacy dives

Retired (legacy-keeps-dive-shape). Legacy's jump, pack, land and bail read dives as legacy nosedive left them, state links and meta alike (see [dive](../.nosedive/kinds/01a1c72b-a065-7e5b-9c4f-271115cffbe5.md), Shape), so seeding a hero that wears legacy and not work rewrites no dive: this migration stays declared, so a hero config that lists it still reads, and returns no changes, saying nothing. A hero this migration converted before it was retired gets its state links back from [legacy-dives-restored](01a1cb89-3807-7929-8b9f-a95284af753a.md).

It still converts a hero wearing work, whose loop reads work's shape, not legacy nosedive's (mi feat legacy-dives), reading every doc in the hero's roots: that is the one move from legacy to work. A hero wears work when a cape its base wears is registered by work's repo doc, `01a15ba8-0bff-7ce3-83dc-e08af3633e26` as core's legacy-capes writes it, or was built from work. "The dive kind" below is work's.

- **State links**: a `landed.dive`, `bailed.dive`, `planned.dive`, `jumped.dive` or `packed.dive` link, from whatever doc holds it (a feat, an effort, a bug), becomes `dives.feat`, its other attributes kept (legacy-dive-states). Other `.dive` rels, such as `context.dive`, are left as they are (legacy-other-dive-rels).
- **Outcome**: a dive any of those links calls `landed` gets `meta.outcome: landed`; else one called `bailed` gets `bailed`; planned, jumped and packed ones get none.
- **Memo-dives**: a target whose kind is not the dive kind, as legacy land left landed and bailed dives, becomes one: `kind: dive`, its canonical scope the kind's owner's, copied from a dive of that kind in the hero (legacy-memo-dives).
- **Feat**: a dive with no `meta.feat` takes the id its `meta.effort` names, by id or by name, else the doc that links it.
- **Meta**: `meta.effort` goes; any other key the dive schema does not have (`diver`, `packer`, `outcome`, `feat`) moves into a `## Legacy meta` section of the dive's body, one `- <key>: <value>` line each (legacy-dive-meta). `diver` and `packer` are kept as they are (legacy-open-dive-diver); jump takes over a bare-email diver for that email (legacy-bare-diver).

It says how many links and dives it changed. Run again, it finds nothing left to change, so removing it from config is safe, and so is leaving it in a hero that wears legacy alone.
