# Legacy patches

Turns the work a legacy hero packed as patch memos into dive refs, where jump, legacy's or work's, finds a dive's work (mi decisions legacy-patches-push, legacy-patches-which). It runs after [legacy-dives](01a1b31b-dffb-7398-9a9e-8bcd257167b5.md), on each dive that is open or bailed: a doc a hero doc links `planned.dive`, `jumped.dive`, `packed.dive` or `bailed.dive`, as legacy nosedive left it, whatever its kind, a bailed one being a memo; in a hero wearing work, where legacy-dives has made work's dives, a dive of work's or legacy's kind with no state link and no landed outcome. It records what it did on each dive it migrates, and removes the patches it pushed (see Recording), and no other doc, so it stays for a hero that wears legacy alone:

- **Each writable scope**, one with a `work-branch` and a `ref`, the commit legacy pinned it to: the patch chain the dive links for that repo (`rel: patch` to its head, `rel: next` onward, `meta.patch` naming a `git format-patch` file) is applied onto the pin with `git am`, in a scratch worktree of the user's cache of the repo; a `dirty.<repo>` patch, uncommitted work, is committed last as `pack(<dive name>): work in progress`, which jump puts back in the working tree. The result, the pin itself when there are no patches, is pushed to `refs/nosedive/<hero id>/dives/<dive id>` on the repo's origin, so jump resumes the dive where legacy would have.
- **The hero's own**: a `bridge-wip` patch, the hero's uncommitted kb changes, is applied onto the hero's trunk as one `pack(<dive name>): work in progress` commit, pushed to the hero's own dive ref on its origin, which jump replays onto the dive's branch.

A dive ref that exists already is left as it is, the work pushed there since being newer. A patch that no longer applies, a pin origin does not have, or a patch memo that is gone is named and passed over, as retrying would not change it. A push or a fetch that fails makes the migration wait, saying what failed: nothing is recorded, and the next seed tries again, the refs it pushed already being found and left. It says what it pushed.

## Recording

What it did to a dive is written on the dive, so that running it again, as removing it from config and seeding does, never builds a dive twice (legacy-patches-records-and-cleans):

- A dive with a `migrated` section, `## <iso time> migrated`, is migrated: skipped whole, with no build and no network, whatever became of its refs, as the loop deletes one when a pack has no work or a bail ends the dive.
- Otherwise, once every repo of the dive is dealt with, one such section is appended (headed as record-dive heads the loop's), a line per writable repo and for the hero, each `- <repo>: pushed <n> patches to <ref>` or `- <repo>: already on origin`, when its ref was there before this run, or `- <repo>: passed over: <why>; its work needs patching by hand on jump, from <patch files>`, repo-relative; the clause after the reason is left out when there are none. A patch chain whose memo is gone is a line of its own, headed `patches`. jump repeats each passed-over line as a warning.
- A dive whose push or fetch waits gets no section, and nothing is removed for it: the next seed tries it again.
- Once `git ls-remote origin <ref>` returns the commit the migration just pushed, that chain's `patch` links on the dive, its patch memos, followed by `next`, and the files their `meta.patch` names are removed. A chain passed over, or whose ref was there already, keeps all of them.

It returns the paths of the docs it wrote and the files it removed, which the migration framework commits (run-cape-migrations): `git add` and `git commit` of a pathspec take a deletion as they take a change. Every write is made after the last dive is built, and none when it waits, so a wait leaves the tree as it found it.
