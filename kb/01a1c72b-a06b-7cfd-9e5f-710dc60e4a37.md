# Jump

## Usage

Work's jump as its main had it at 260eb82, with legacy's own dive kind (see [dive](../.nosedive/kinds/01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)). An agent jumps when the pilot says to: "jump", "jump on <thing>", "work on <thing>" and the like, never on its own initiative.

`<ref>` is a feat's or a dive's quid. A feat is any doc one of the hero's roots reaches through links whose rel ends `.feat`, a root of kind cape aside, since its feats are actions, a memo unless it has a kind of its own; a doc nothing reaches that way is refused, naming how to link it in. Its `scopes` name the repos it works in, legacy's shape: an entry keyed by a repo doc's quid, with `work-branch` naming the branch its work goes to, and an entry with none, or a bare quid, read-only. A dive's read-only scope is written as an entry with none (`<repo>: {}`), which core reads a bare quid as.

Uncommitted changes: off a dive branch, an unclean hero tree is refused (jump-needs-clean-tree); on any path, a scope checkout jump would move that has uncommitted changes or untracked files is refused, each named, before anything moves. A checkout already where the dive wants it, as on a dive branch, is left as it is, changes and all. A checkout jump moves has its ignored files swapped for the feat's pack, and pack's work-in-progress commit on this dive is undone, so packed work comes back uncommitted.

Jump ends by telling the agent that jumped to do the dive's work now, from its brief to its feat's Done when, and to pack or land it only when the pilot asks.

While the dive is on deck:

- Commit freely in a writable scope's checkout, in small commits, and heed what its hooks say. Never push one: land publishes to the feat's work branch, and pack and bail to the dive's refs. Nothing blocks a push, as legacy's sentinel did, so the restraint is the agent's.
- Commit nothing in a read-only scope: pack and land refuse what it holds, which has nowhere to go.
- Hero docs the dive changes are committed on the hero's dive branch; land takes them to its home.
- Record progress with `pass --turn <dive> <summary>`. Leave the brief as it is: it records what the dive was started for.

## Where it is jumped from

A dive is jumped from a branch of the hero, its home, and everything hero-side for it goes there (records-on-jumped-branch): the jump, pack, land and bail records, and the hero's commits when it lands, each pushed to the home's upstream. Branches of the hero do not know of each other's dives until they are merged; trunk is one such branch. Jump puts the hero on the dive's branch, `nosedive-<token>-<dive id>`, the token being the home's holder token, its 12 hex digits (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), cut from the home's tip after the jump record, and every writable scope's checkout on a branch of the same name (dive-branches). Pack, land and bail switch the hero back to its home, found as the local branch whose holder token the dive branch names (loop-returns-home).

## On a dive branch

On a dive branch, jump takes only that branch's dive, with or without `<ref>`, and records nothing: each scope whose checkout is missing or elsewhere is put where the dive wants it, and a checkout already there is left as it is, so no commit on any of them is lost; another `<ref>` is refused: pack, land or bail it first (one-dive-branch-per-checkout).

A dive that is over, landed or bailed, is refused on every path, before anything changes: named by its quid, as the dive on a dive branch the hero is on, and as the dive of a dive branch this checkout has left over. The refusal names how it ended and, where its branch is still here, says to leave it: switch to its home, the branch it was jumped from, and delete the branch. Pack, land and bail refuse an over dive, so one taken up again could never be put down.

## Off a dive branch

The branch the hero is on is the home. Refused, naming why, before anything moves:

- while the hero's working tree is not clean (jump-needs-clean-tree);
- when the home has no upstream, so the dive's records would be stranded in a local branch: push it first, as `git push -u origin <branch>`;
- when the home holds commits its upstream lacks, after fetching it and fast-forwarding a home that is behind: push them first;
- while this checkout has a dive branch, any `<ref>` but its dive: pack, land or bail it first; its own dive's `<ref>` switches the hero onto it and goes on as on a dive branch (one-dive-branch-per-checkout).

A `<ref>` is a doc's quid, its name, or a path ending `<quid>.md`, as `next` prints beside it (listed-paths-accepted).

Without `<ref>`, jump takes the one open dive this checkout holds without a branch, else the one nobody holds that the pilot packed or nobody has touched; with none or several, it refuses, naming each.

- **A dive**: refused when it is over; when another checkout holds it, naming the branch of this checkout it is held from when it is one, else `pack it there` (held-by-checkout); a diver legacy wrote, a bare email with no token, holds it in no checkout in particular, so a checkout whose git user.email it is takes it over and anyone else is refused, naming the email (legacy-bare-diver); and, without `--sure`, when another email packed it: `--sure` takes it over, its work in progress included (take-over-with-sure). A dive this checkout holds whose branch is gone is jumped again without a record: its branch is cut from the home's tip and its packed hero work replayed, so only what was never packed is lost.
- **A feat**: a bare attempt at all of it (feat-jumps-bare). Refused while the feat links any dive `dives.feat`, over or not, `--sure` included, since a bare jump would start the feat over: the refusal says to finish and drop those dives, or to plan another dive saying what it does, `nosedive crud nosedive-legacy:dive <gist> --meta:feat <feat> --section:Brief -`, and jump that. Otherwise, without `--sure`, refused unless `next` would list it, a non-durable leaf: a durable doc, or one with another link whose rel ends `.feat` other than `parent.feat`, takes `--sure` (sure-off-fringe). It mints a dive on it (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), named `<last 6 hex of its id>.<feat name>` (dive-name-hex-first), gisted "An attempt to complete <feat name>", copying its scopes, naming the feat in its `meta.feat`, and linking it from the feat as `dives.feat`; then jumps it. The feat, its `## Dropped` included, is that dive's brief.

Then, in order:

1. A checkout to be moved with uncommitted changes or untracked files is refused, naming each, before anything moves.
2. The jump record, `jump(<dive name>): <summary>`, is committed on the home: the dive minted when jumping a feat, `diver` set to `<email>#<token>`, `packer` cleared, each scope's `ref` set to the dive's newest ref on its origin, and a `## <timestamp> jumped` section. It is pushed to the home's upstream; when that moved meanwhile, jump drops the record, fetches and fast-forwards, refuses if someone else now holds the dive, and records again.
3. The hero's dive branch is cut there and checked out, and the dive's newest ref on the hero's origin, its packed hero work, is cherry-picked onto it. A conflict aborts the pick and leaves the hero on the dive branch at the record, naming the ref the work is on.
4. Each writable scope's checkout is put on the dive branch, hydrated detached with core's hydrate-repo when missing, then switched; moved when there for other work, its commits origin lacks pushed to an orphan ref first. Where the dive's newest ref holds what the branch lacks, the branch moves to it; when the work branch on origin has moved on, the work is rebased onto it, a conflict aborting the rebase. Each read-only scope's checkout is detached at origin's trunk.

Then each checkout moved from other work has its ignored files swapped for the feat's pack (see dive), never those under a configured workspace (see pack), and pack's `work in progress` commit is undone, when it names this dive, as `pack(<dive name>): work in progress` or, as pack named it while feats grouped the loop's commits, `feat(<feat name>): pack work in progress on <dive name>`; another dive's is left alone in the hero and each scope, so the work it held comes back uncommitted. It prints the dive's path, its feat's and each checkout's.

On every path that succeeds, on a dive branch included, it then prints `Now do the dive's work, from its brief, <path>, to its feat's Done when; pack or land it only when the pilot asks.`, the brief being the dive's when it has a `## Brief`, else its feat (jump-starts-the-work).

## Canonical dives

A feat's dive is minted as `nosedive-legacy:dive` (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), found with find-kind and pinned with core's pin-of, so the dive carries legacy's canonical scope; a schema that is not published refuses the jump before any checkout moves. Dives and feats are recognised by doc-kind, never by the text of `kind`.
