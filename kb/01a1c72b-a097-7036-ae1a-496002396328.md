# Land

## Usage

Work's land as its main had it at 260eb82, on legacy's dive kind. An agent lands only when the pilot says to: "land", "ship <thing>" and the like. Land runs no gates, as legacy's land ran its `land.gate`s: run `nosedive test` first, `--full` for the feat's gates too, and land once they pass. A landed dive is over: it is never jumped again.

Each refusal below names what to do. A work branch that moved is never pushed past: `pack`, then `jump` the dive, which rebases its work onto the branch, then land again; never `git push --force`, which would drop what the other push added.

`<dive>`, when given, must be the dive on deck. Refused, before anything is pushed:

- off a dive branch, or when the dive's home is gone: recreate it (loop-returns-home);
- when the home holds commits its upstream lacks, after fetching it and fast-forwarding a home that is behind;

- while the hero or a checkout has uncommitted changes, naming each: commit them first;
- while a read-only scope has commits origin lacks;
- while a work branch has moved to a commit the scope's HEAD does not contain. The recourse is `pack`, then `jump`, which rebases the work onto the branch.

Each commit it publishes that no branch on origin holds is stamped first with `Nosedive-Dive: <dive id>`, `Nosedive-Feat: <id>`, the dive's first durable feat ancestor (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), and the nosedive co-author trailer (see commit-message), where the commit lacks them. A commit that carries a nosedive co-author already, of any version, from an earlier stamp or a rebase, gets no second; another's co-author does not stand in for it. The hero's record, `land(<dive name>): <summary>`, carries it too.

Each writable scope whose checkout is on the dive's local branch and holds work its work branch lacks is pushed to it, a fast-forward or the branch's creation; any other is unchanged. Then each scope's ignored files are packed for its feat, every ref of the dive is deleted on origin, and each checkout is left detached at what it holds, its local branch deleted.

The hero's own work, the commits on its dive branch, rides to the dive's home (records-on-jumped-branch): the dive branch is rebased onto the home, its commits stamped, the hero switched back to the home, fast-forwarded to them, and its dive branch deleted; then `outcome: landed` set, `diver` cleared and a `## <timestamp> landed` section recording each push are committed on top, and the home is pushed to its upstream, rebased onto it first when it moved meanwhile. So the hero's work for the dive sits between its jump and land records.
