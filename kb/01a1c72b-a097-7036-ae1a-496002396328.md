# Land

## Usage

Work's land as its main had it at 260eb82, on legacy's dive kind and the dives legacy nosedive wrote (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md), Shape). An agent lands only when the pilot says to: "land", "ship <thing>" and the like. A landed dive is over: it is never jumped again.

Land runs gates before it pushes anything, as legacy's land ran them, through the same runner as `test`. It collects every `land.gate` link on the dive, on the repos it scopes and on the dive's feat and its ancestors along `.feat` links (see test), never a sibling's or a descendant's, so a dive on a parent runs none of its children's gates; a gate reached twice keeps its first link's attributes. Gates run tallest `gate-height` first, ties in the order found, each seeing the dive's checkouts as land is about to push them; `test-is-flaky: true` turns a failure into a warning. A selected gate with no `meta.test-script`, or whose doc or script has uncommitted changes, refuses the land before anything runs, named. One blocking failure pushes nothing and leaves the dive held. A `## Land report <timestamp>` section is appended to the dive either way, committed on its branch: a passing gate takes one line, a failing one its script and stderr. A dive with no gates lands as before, with no report.

Each refusal below names what to do. A work branch that moved is never pushed past: `pack`, then `jump` the dive, which rebases its work onto the branch, then land again; never `git push --force`, which would drop what the other push added.

Before it plans a push, each scope checkout of the dive loses legacy nosedive's render-sentinel pushurl, saying so (see [dive-on-deck](01a1c72b-a0a6-7a64-836f-167c23ffa097.md), Render sentinels).

`<dive>`, when given, must be the dive on deck. Refused, before anything is pushed:

- off a dive branch, or when the dive's home is gone: recreate it (loop-returns-home);
- when the home holds commits its upstream lacks that nosedive did not commit, after fetching it: push or drop them first, each listed. Those nosedive committed are replayed onto the upstream if it moved, nosedive still their committer, and pushed with land's record (see jump); a replay that conflicts is refused as the others are;

- while the hero or a checkout has uncommitted changes, naming each: commit them first;
- while a read-only scope has commits origin lacks;
- while a work branch has moved to a commit the scope's HEAD does not contain. The recourse is `pack`, then `jump`, which rebases the work onto the branch;
- when the home's copy of the dive doc changed since the dive began and the dive branch's copy does not begin with it (the moved-home guard, see dive-on-deck): `<doc> on <home> changed since this dive began, by <sha> <subject>, so nothing was landed and every turn is still on <dive branch>: revert that change on <home>, or ask whoever made it to, then run \`nosedive land\` again`.

Turns live on the dive branch and its dive ref, and reach the home only when land, pack or bail puts the dive down: land publishes them in its record and deletes the dive's refs. Uncommitted changes are not backed up, and land refuses them rather than leave them behind.

Each commit it publishes that no branch on origin holds is stamped first with `Nosedive-Dive: <dive id>`, `Nosedive-Feat: <id>`, the first durable feat ancestor of the dive's feat or of the doc that links it (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), and the nosedive co-author trailer (see commit-message), where the commit lacks them. A commit that carries a nosedive co-author already, of any version, from an earlier stamp or a rebase, gets no second; another's co-author does not stand in for it. The hero's record, `land(<dive name>): <summary>`, carries it too.

Each writable scope whose checkout is on the dive's local branch and holds work its work branch lacks is pushed to it, a fast-forward or the branch's creation; any other is unchanged. Then each scope's ignored files are packed for its feat, every ref of the dive is deleted on origin, and each checkout is left detached at what it holds, its local branch deleted. A ref of the dive under a name from before the ref scheme holding work this dive did not see refuses the land, naming it; the dive's refs under every token, and the markers of the put-down, go with the dive, and nothing of nosedive's is left in a local ref.

The hero's own work, the commits on its dive branch, rides to the dive's home (records-on-jumped-branch): the dive branch is rebased onto the home, its turn commits left out of the replay, since the record holds their sections (turns-publish-when), so each turn's section sits once on the home and no empty commit is left, its commits stamped, the hero switched back to the home, fast-forwarded to them, and its dive branch deleted; then the dive's link moved to `landed.dive` on the docs that hold it, which is how it ends, `diver` cleared and a `## <timestamp> landed` section recording each push are committed on top, built on the dive branch's copy of the dive doc, which holds every turn, so the record carries them all, with a `- turns: <n>` line when the dive made any (a turn is committed on the dive branch and pushed to the dive's ref, never to the home, until this record; the turns already on the dive ref are not pushed again, since land deletes that ref), the rest of the dive's meta untouched, and the home is pushed to its upstream, rebased onto it first when it moved meanwhile. So the hero's work for the dive sits between its jump and land records.

A rerun of a land that failed after its record was published finds that record on the home and does not make another. The turns written after the failed run, on the dive branch since, are appended to the home's copy of the dive doc in one more commit, `land(<dive name>): turns written after the failed land`, each only once: a turn whose section the home's copy holds already is skipped (turns-publish-when). Its turn commits are left out of the hero work it replays, as in the first run.

The moved-home guard is judged on a fresh fetch taken just before the first push. A home that moves after a work branch is pushed but before the record is, so that the refusal above would find the dive part landed, is not reported as nothing changed: the refusal says land is only partly done, names the work branches it pushed and what is not yet published (the hero's work and the record), says every turn is still on the dive branch and the other change is untouched, and names the command to run again. The home's copy of the dive doc still moved, so the rerun refuses the same way until that change is reverted on the home, and the message says so; once it is, the rerun finishes without stamping the work twice. A home that moves without touching the dive doc is planned again from a fresh fetch and finishes in the same run.

Its own markers are refs on origin under the token of the checkout that holds the dive (nosedive-ref-scheme): `land.<dive id>.record`, the record it is about to push, and `land.<dive id>.base`, the dive branch's tip it was built from, in the hero's origin, and `land.<dive id>.<repo id>.source` and `.tip`, the tip the scope held and the stamped tip it publishes, in each scope's. Each is pushed on its own, with no `--atomic`, which not every remote supports, before the update it guards, so it records intent: the marker points at the commits about to be published, which reach origin with it. A land stopped after a marker is read by a rerun from any checkout, which finishes it, and a marker equal to what was published counts as done. They are read under any token, so a checkout that took the dive over with `jump --sure` finishes a land another began. A rerun refused for another reason, as when a work branch has moved on from what a stopped run published, says land is only partly done, naming what the markers show published, never that nothing was landed. They are deleted once the record is on the home, the scopes' last; one that is left is equal to what was published, so a rerun finds it done, and the next land or bail of the dive deletes it.
