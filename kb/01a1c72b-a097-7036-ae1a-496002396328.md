# Land

## Usage

Work's land as its main had it at 260eb82, on legacy's dive kind and the dives legacy nosedive wrote (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md), Shape). An agent lands only when the pilot says to: "land", "ship <thing>" and the like. A landed dive is over: it is never jumped again.

Land runs gates before it pushes anything, as legacy's land ran them, through the same runner as `test`. It collects every `land.gate` link on the dive, on the repos it scopes and on the feats reached from the dive's feat along `.feat` links only; a gate reached twice keeps its first link's attributes. Gates run tallest `gate-height` first, ties in the order found, each seeing the dive's checkouts as land is about to push them; `test-is-flaky: true` turns a failure into a warning. A selected gate with no `meta.test-script`, or whose doc or script has uncommitted changes, refuses the land before anything runs, named. One blocking failure pushes nothing and leaves the dive held. A `## Land report <timestamp>` section is appended to the dive either way, committed on its branch: a passing gate takes one line, a failing one its script and stderr. A dive with no gates lands as before, with no report.

Each refusal below names what to do. A work branch that moved is never pushed past: `pack`, then `jump` the dive, which rebases its work onto the branch, then land again; never `git push --force`, which would drop what the other push added.

`<dive>`, when given, must be the dive on deck. Refused, before anything is pushed:

- off a dive branch, or when the dive's home is gone: recreate it (loop-returns-home);
- when the home holds commits its upstream lacks, after fetching it and fast-forwarding a home that is behind, but for those a turn left unpushed, which land's record pushes;

- while the hero or a checkout has uncommitted changes, naming each: commit them first;
- while a read-only scope has commits origin lacks;
- while a work branch has moved to a commit the scope's HEAD does not contain. The recourse is `pack`, then `jump`, which rebases the work onto the branch.

Each commit it publishes that no branch on origin holds is stamped first with `Nosedive-Dive: <dive id>`, `Nosedive-Feat: <id>`, the first durable feat ancestor of the dive's feat or of the doc that links it (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)), and the nosedive co-author trailer (see commit-message), where the commit lacks them. A commit that carries a nosedive co-author already, of any version, from an earlier stamp or a rebase, gets no second; another's co-author does not stand in for it. The hero's record, `land(<dive name>): <summary>`, carries it too.

Each writable scope whose checkout is on the dive's local branch and holds work its work branch lacks is pushed to it, a fast-forward or the branch's creation; any other is unchanged. Then each scope's ignored files are packed for its feat, every ref of the dive is deleted on origin, and each checkout is left detached at what it holds, its local branch deleted.

The hero's own work, the commits on its dive branch, rides to the dive's home (records-on-jumped-branch): the dive branch is rebased onto the home, which drops its copy of each turn, since the home holds that change already (see turn), so each turn's section sits once on the home and no empty commit is left, its commits stamped, the hero switched back to the home, fast-forwarded to them, and its dive branch deleted; then the dive's link moved to `landed.dive` on the docs that hold it, which is how it ends, `diver` cleared and a `## <timestamp> landed` section recording each push are committed on top, the rest of the dive's meta untouched, and the home is pushed to its upstream, rebased onto it first when it moved meanwhile. So the hero's work for the dive sits between its jump and land records.
