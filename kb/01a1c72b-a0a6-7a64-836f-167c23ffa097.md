# Dive on deck

Finds the dive on deck from the hero's branch (dive-branches), among the open dives: the docs of legacy's dive kind that a doc of the hero links `planned.dive`, `jumped.dive` or `packed.dive`, which legacy, not core, reads, core's feat-tree following no such link (see [dive](01a1c72b-a065-7e5b-9c4f-271115cffbe5.md), Shape): a branch `nosedive-<token>-<dive id>` whose dive id names an open dive in the hero, and whose `diver` carries that token; and its home, the local branch whose holder token is that token (loop-returns-home). It returns them with the dive's state and the docs that link it, its feat, which `meta.feat` or `meta.effort` names, else the doc that links it, and its scopes. A dive whose link says landed or bailed is over, and refused so. Given a dive's quid, it refuses unless that is the one. Off a dive branch it refuses, naming `jump`; a dive branch whose dive is over or held by another token, as a copied branch's would be, is refused, as is a home that is gone: recreate it.

Each scope carries its repo doc, its checkout, the repo's trunk, the work branch, if any, and whether its checkout is the dive's: on the dive branch when writable, present when read-only. Nothing is hydrated or moved.

## Kind identity and scopes

Docs are told apart by core's doc-kind, not by the text of `kind`: a dive is a doc whose name is `dive` and whose canonical owner is legacy or none, as legacy nosedive wrote it, not work, a repo doc is core's by its place in `.nosedive/repos`, and a cape root is skipped when walking feats. The kind of a feat is found with find-kind, spelled in the hero's terms, to learn whether it is durable; a dive's first durable ancestor is sought from its feat and from each doc that links it, through core's feat-tree, which reaches those from their parents.

Only an entry keyed by a repo doc the hero registers is a work scope. Every other entry is not the loop's to read: the one with `canonical: true` naming the owner of the doc's kind, and any meta entry keyed by a seeded id carrying `version`, `schema` or `meta`. None is checked out, and when a dive's refs are rewritten each is kept exactly as parsed.

## Turns and records

The module also holds what turn, jump, land, pack and bail share for turns (turns-publish-when, turns-pushed-where). `turnCommits` lists the turn commits in a range: the subject `feat(<feat name>): pass turn`, or `pass: turn` where core found no feat to group it under, whichever feat that is, since legacy's dives are no feats of their own, not a merge, each changing only the dive doc, whoever the committer is, since a rebase makes the person the committer. `recordBase` gives the dive doc a put-down's record is built on, the dive branch's copy, which holds every turn, and counts the turns the dive made since its base. It is where the moved-home guard sits: the home's copy of the dive doc at its tip, compared with its copy at the dive's base, is fine unchanged, or when the dive's copy begins with it, as a dive in flight with turns already on main has; otherwise it refuses, before anything is changed, with `<doc> on <home> changed since this dive began, by <sha> <subject>, so nothing was put down (landed, for land) and every turn is still on <dive branch>: revert that change on <home>, or ask whoever made it to, then run \`nosedive <command>\` again`. When an earlier run of the put-down already published part of the work, which the home moving after the work and the dive refs were pushed leaves, it instead says the command is only partly done, names what was published and what was not and the command to run again, and still touches nothing (put-down-home-race); `assertHomeUnmoved` judges the home on a fresh fetch just before the first push, so only a move inside that window gets the partial message. The push of the record, fast-forward only and leased on the home's tip, is what stops an overwrite; the refusal names the cause and never throws a turn away. The record commit itself is the record-dive function's, given the dive branch's copy as its base. Nothing here puts a turn on the home.

The dive's ref in each repo is `diveRef`, under the diver token, as `ownedRef` makes every nosedive ref on origin: `refs/nosedive/<owner>/<cape id>/<slug>` (nosedive-ref-scheme). The cape id is work's, `WORK_ID`, in legacy too, so a dive has one ref per token whichever of the two capes touched it (work-owns-dive-refs). `backUp` is the turn's push: each writable scope's committed tip, then the hero's, to that ref, which only this checkout writes, so the push replaces it, a rebase included; it commits nothing, names the repos holding uncommitted changes, reports a push that is refused or offline and leaves the work committed, and pushes no hero ref after a scope's push failed. `diveRefs` reads the dive's work under any token or older name, `diveMarkers` its markers, and `keepOrphans` writes commits moved off a branch to a bundle in the hero's packs dir, never to a ref.

## Render sentinels

Legacy nosedive, up to 2026.9.18, wrote a `remote.origin.pushurl` into each checkout's worktree config to block pushes: `nosedive-render-587d3f73-2534-5179-b111-ce6c83d6814d` on a writable scope (land-only), `nosedive-render-c4e93002-2925-58bd-9b70-d917017a9fc7` on a read-only one. Its land pushed to the resolved URL, past them; the loop pushes to `origin`, which they break, and core reuses the checkout, so they stay.

`dropRenderSentinels` removes either value from a checkout's worktree-scoped `remote.origin.pushurl`, the rest of that config kept, and says one line for each checkout it changed. Any other pushurl, or a sentinel set at another scope, is left (render-sentinels-dropped). Jump calls it on each scope's checkout it reuses or hydrates; land, pack and bail on each scope checkout of the dive before they plan a push.
