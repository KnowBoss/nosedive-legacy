# Turn

## Usage

`pass --turn <dive> [<summary>] [--next <gist>] [--label <label>]` records progress on the dive on deck, the one the hero's dive branch names, as found by dive-on-deck. A different dive is refused. `-` as summary reads stdin.

Append a section headed `## <ISO 8601 timestamp>[ <label>]`, then the summary when given, then `Next: <gist>` when given. Use core's hero-zone timestamp helper once available; until then use UTC with `Z`. Refuse when neither summary nor next is given, or next contains more than one line. Two turns append in order. Edit through pass so each turn makes one ordinary pass commit. The gate sets no commit subject; core's pass owns it.

## Reaching the home

A turn is committed on the dive branch, where the hero is, and also on the dive's home, the branch it was jumped from, and pushed to the home's upstream, so the dive's log is on the hero's trunk as it is written (turns-on-jumped-branch). It stays a pass gate (turn-stays-a-pass-gate): the gate asks pass, through `ctx.committed`, to call it once the pass has committed, and then takes pass's own commit onto the home without checking the home out (turn-reaches-home-how):

1. The merged tree is made with `git merge-tree --write-tree --merge-base=<commit>^ <home tip> <commit>`, a commit is made from it on the home's tip with the turn commit's message, author, committer and dates, and the home's ref moved to it. The working tree, the index and the dive branch are not touched, so the hero's other work in progress stays as it is.
2. The home is pushed to its upstream: its new commit, and any an earlier turn left unpushed beneath it, and nothing else (turn-pushes-for-anyone): whoever records a turn, a subagent too, pushes it. When the upstream moved, the gate fetches it and takes the home's commits it lacks onto its tip the same way, then pushes again, up to three times, as jump's record does.

What it prints after pass's own output, and whether it exits 0:

- Pushed: `turn: <sha> on <home>, pushed to <remote>/<branch>` on stdout, exit 0.
- The merge conflicts, as when the home's copy of the dive doc was changed by hand: the home stays as it was. `warning: the turn is on the dive branch only: it conflicts with <home> (<git's words>); land carries it` on stderr, exit 0.
- The push is refused or the upstream cannot be reached, a protected trunk or no network: both commits stay made (turn-push-refused). `warning: the turn is on <home> but not pushed to <remote>/<branch>: <why>; the next turn, pack or land pushes it` on stderr, exit 0.
- A core that gives gates no `ctx.committed`: `warning: this nosedive cannot put the turn on <home>, so it is on the dive branch only: update nosedive core` on stderr, exit 0.

A turn that reached the dive branch is recorded, so each of these exits 0; only a turn that could not be recorded there, a refusal, exits 1. The commit's change to the dive doc is the same on both branches, so land's rebase finds the dive branch's copy already on the home and drops it. That holds while nothing else edits the dive doc: crud refuses to (held-dive-doc-edits, see dive-shape).
