# Legacy dives restored

Undoes, for a hero that wears legacy and not work, what [legacy-dives](01a1b31b-dffb-7398-9a9e-8bcd257167b5.md) did before it was retired (legacy-keeps-dive-shape). That version rewrote each state link to `dives.feat` and gave landed and bailed dives `meta.outcome`, a shape legacy's loop no longer reads: such dives are not listed as open, and jump refuses them as hanging from no doc. Legacy's loop at that version minted dives the same way, so they are restored too.

- **Links**: a `dives.feat` link, from whatever doc in the hero's roots holds it, to a dive of legacy's (see [dive](../.nosedive/kinds/01a1c72b-a065-7e5b-9c4f-271115cffbe5.md)) becomes the state link the dive's meta says it stood for, its other attributes kept: `landed.dive` or `bailed.dive` by `meta.outcome`; else `jumped.dive` when it has a diver, `packed.dive` when it has a packer, and `planned.dive` when it has neither. A `dives.feat` link to any other doc is left as it is.
- **Outcome**: each dive so relinked loses `meta.outcome`, which the loop neither reads nor writes.
- **Left as they are**: the dive's kind and canonical entry, which legacy's dive kind accepts; `meta.feat`, which the loop reads first; and a `## Legacy meta` section, whose values legacy-dives wrote as text. Where several docs linked one dive by different states, legacy-dives kept only the strongest, which every link now takes, as the loop moves them.

A hero that wears work is left as it is, since work's loop reads `dives.feat`, and so is a hero with no such link, so it says nothing on a fresh hero, and run again it finds nothing to change. A hero that has already seeded gets it with `nosedive seed --migrate`. It says how many dives and docs it changed.
